# 流式对话

前端聊天使用 `POST /api/v1/chat/stream`，通过 fetch 读取 SSE。原来的 `POST /chat` 保留，便于兼容现有脚本。

事件格式为 `data: {JSON}\n\n`：

| type | 用途 |
| --- | --- |
| status | 正在思考或处理任务的进度提示 |
| reset | 新一轮模型回复开始，清除工具调用前的临时文本 |
| delta | 追加模型生成的正文片段，不输出工具参数或推理字段 |
| done | 最终完整回复、artifacts 和 pending_approval_id |
| error | 明确提示中断，客户端保留已显示片段并标记不完整 |

LangGraph 消息流驱动真实模型分段输出，非完整回复到达后再模拟打字。工具执行及检查点保持原流程，邮件只生成审批卡，发送仍由审批接口执行。完整回复及业务卡片在 done 发送前写入聊天记录。

离开页面会中止浏览器读取；后端已经开始的执行仍继续完成并保存，避免丢弃已经产生的业务操作。不要把断开连接当成撤销工具操作。失败的片段不会作为完整回复写入后端。
