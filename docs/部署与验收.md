# 部署、演示与验收

更新：2026-10-15。运行边界为单应用实例、单 worker、SQLite 业务库与 SQLite checkpoint。此边界之外的共享限流、分布式调度与任务恢复仍需专门设计。

## 配置与启动

1. 参考 `.env.example` 配置 JWT 密钥（独立随机长值）、模型地址和模型。生产模式拒绝空值、过短与已知默认 JWT 密钥。开发免密码登录入口已删除，使用注册/密码登录。
2. Zotero 启用时还需合法 Fernet key 与独立内部令牌。保管 Fernet key 的安全备份，丢失后无法解密旧绑定；不要把它随数据库备份一同公开。
3. 默认使用 `MAIL_BACKEND=mock` 验收。真实 SMTP 配置投入使用前，单独确认外发目的和收件人；自助提醒开启后会自动发送，给他人的邮件需要审批。
4. `docker compose up -d --build` 使用镜像内的非 root 用户和单 worker。`/health` 为存活检查；`/ready` 检查数据库与提醒 schema 就绪，不代表模型、SMTP 或 Zotero 可用。
5. 默认启用后台提醒；验收或专用无调度进程设置 `REMINDER_SCHEDULER_ENABLED=false`。逐用户检查后等待 60 秒，延迟随任务与 SMTP 耗时增加。健康检查不提供调度互斥。

已有 Docker 数据卷升级：旧卷可能属于 root，非 root 镜像无法写入。先停止应用并备份；Compose 会先运行 `labpilot-init`，以一次性维护身份仅修正 `/app/data`、`/app/logs` 的属主和权限，再启动非 root 主应用。初始化容器无网络、根文件系统只读，不读取密钥或修改数据库内容；遇到符号链接或特殊文件拒绝操作。不要删除数据卷，不要用长期 root 运行替代修复。直接 `docker run` 使用旧卷时也需先完成这一步，不能只测空卷就认为升级成功。

`/ready` 现在执行不更新任何用户行的写事务探针并回滚，可识别“能读但不能写”的数据库；`SELECT 1` 本身不能发现这类故障。

历史身份：后端已停止启动时的 dev→root 数据批量转移，前端也不再把无归属旧缓存归给 root。当前数据保持现状，不会自动将已转移的数据回改。确需恢复旧归属时，先停机、备份并核验业务表、集成凭证和 checkpoint；本次未执行任何用户数据重新归属。

## 运行保护与故障语义

- 参数见 `.env.example`。同一用户的同一 thread 一次只执行一个 chat/stream/resume；全局与用户并发达到上限返回 429，同 thread 冲突返回 409。登录/注册按连接 IP 限流，聊天按已认证用户名计数，不信任客户端随意传入的代理 IP。
- 限流与准入为进程内状态，重启清空。需要多实例时必须增加共享存储或网关方案，不能直接增加 worker 数并宣称限制仍全局有效。
- 模型超时/重试显式配置；图步数、逻辑模型调用、工具调用与操作边界的时间预算分别限制。SDK 自动重试次数并不等于逻辑调用次数；时间预算不能撤回已经开始的操作。
- SSE 队列有界，慢消费者最多等待一次发布窗口后停止投递展示事件，业务仍继续保存。断开页面不会立刻释放仍在运行的执行名额。该线程不是持久任务队列；进程被杀时不能保证继续执行。
- 达到预算后不自动重放工具。下一轮会补齐未完成的工具消息协议，防止历史中的悬空 tool_call 让模型接口失败；这不代表上轮业务已成功。
- 审批恢复先核对 checkpoint 中断和审批 ID；重复决策不重复恢复图。普通邮件 failed/unknown 不自动重发，提醒只对明确 failed 重试，unknown/sending 保留待核查。
- 结构化日志包含 request_id、run_id、耗时、逻辑模型/工具调用数及模型返回的 token usage（供应商未提供时为空）。不记录凭证；关闭异常局部变量诊断。日志不是集中式监控或跨进程计费系统。

## 备份与恢复

备份前停止应用及所有写入，保证业务库与 checkpoint 来自同一业务时点。SQLite 在线 backup API 能保证单个文件一致，但不能让两个分别复制的数据库自动成为跨库事务快照。

```powershell
.venv/Scripts/python.exe scripts/sqlite_snapshot.py --database labpilot.db --checkpoint labpilot_checkpoints.db --output backups/snapshot-20261015 --application-stopped
```

脚本要求两个源文件存在且不同、输出目录不存在；不覆盖原文件，执行完整性检查并生成哈希清单。输出是敏感业务数据，应受访问控制。

恢复时使用新隔离目录，将 `business.db` 与 `checkpoints.db` 配置为 `DATABASE_URL` 和 `CHECKPOINT_DB_PATH`；保留匹配的 JWT/Fernet 配置，先以 mock 邮件、关闭后台调度启动，验证用户数据、报告和审批。确认后再切换，不能将恢复演练直接覆盖正在使用的库。

## 独立演示数据

```powershell
.venv/Scripts/python.exe scripts/seed_demo.py --output .acceptance/demo-new
```

脚本仅创建新目录中的 demo 用户、样例纪要、待办和进展，并生成随机演示密码。启动服务时必须显式指向该目录的两个数据库，使用 mock 邮件；需要演示模型时再配置模型。不要清空开发库来准备演示。

## 回归与验收

```powershell
.venv/Scripts/python.exe -m ruff check app tests scripts
.venv/Scripts/python.exe -m pytest -q
npm --prefix frontend run build
.venv/Scripts/python.exe scripts/acceptance_live.py --real-model --output .acceptance/live-new
```

前三项为本地静态/离线回归；第四项会向配置的外部模型发送合成测试文本并产生费用，强制 mock 邮件、独立数据与真实进程重启。不得改为使用开发数据库或真实收件箱。

浏览器脚本为 `frontend/scripts/browser-delivery.mjs`，环境变量 `PLAYWRIGHT_MODULE` 指向已安装的 Playwright，`CHROME_EXECUTABLE` 可指定 Chrome，`LABPILOT_PYTHON` 可指定解释器。脚本会启动本机独立服务，实点登录、编辑、刷新和重新登录，保存结果与截图；它不调用真实模型。

CI 配置为 `.github/workflows/ci.yml`：后端静态检查、pytest、前端构建、镜像构建。需要将项目置于 Git 仓库并推送到有 Actions 的远端后才能获得托管 CI 结果；本地执行同等检查不等于 GitHub CI 已运行。

镜像默认启动与健康检查可用 `python scripts/container_smoke.py --image labpilot:internship-20261015` 验证；脚本只操作自己创建的随机名测试容器，无网络、无业务数据卷，结束后清理该容器。
