# 注册失败：旧 Docker 数据卷权限修复

2026-10-15 用户报告实际服务注册返回500。容器堆栈为 SQLite `attempt to write a readonly database`：应用 UID999，旧数据目录、数据库与日志卷归 UID0 所有且不可写。

此前新临时库、tmpfs和浏览器验收没有覆盖 root 属主旧卷升级场景，这是先前验收的覆盖缺口，不是用户名或登录状态导致。

## 修复

- 增加一次性 `labpilot-init` 服务，读取镜像内实际应用账号 UID/GID，仅处理两块专用卷；无网络、根文件系统只读，完成后退出。主应用仍以非 root 启动，不使用 chmod777。
- Compose 主应用等待初始化成功；Zotero 叠加配置合并依赖，保留初始化前置条件。
- `/ready` 增加无行更新、随后回滚的写事务探针，只读数据库返回503而非200。
- 后台调度启停可通过 Compose 环境参数控制，用于升级验收避免意外补发邮件。

## 现场验证

1. 停止 LabPilot，完整复制业务与 checkpoint 所在数据卷以及日志卷到项目内 `backups/registration-permissions-20261015-155706/`。未删除数据卷，未重置账号。
2. 初始化修复权限并重启，逐表比较备份与实际数据库：15张业务表行数与内容指纹一致。
3. 对实际18000端口创建随机临时账号：注册201、登录200、鉴权待办查询200。只清理这次测试账号及其审计记录，保留其他用户数据。
4. 验收期间暂停后台调度，没有通过注册验收发送邮件。用户随后明确授权恢复已开启的真实 SMTP 自动提醒，验收后恢复。
5. 新增卷权限保留内容与只读库 ready 返回503的回归；完整回归131 passed，静态检查通过；线上容器 healthy，ready=200，主应用UID999、数据库可写，后台调度已恢复。

后续正常 `docker compose -f docker-compose.yml -f docker-compose.zotero.yml up -d --build` 会先执行权限初始化，再启动应用。备份含业务数据，已被 `.gitignore` 与 `.dockerignore` 排除，不应公开。
