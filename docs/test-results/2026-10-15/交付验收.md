## 执行中发现的问题及修正

1. Windows 沙箱不能正常创建 asyncio 的本地套接字，部分测试最初无法启动；在获准的运行环境下重新完成。此类环境失败不算项目测试通过。
2. 真实模型验收最初被自动审批拒绝。用户明确授权合成测试文本发送到已配置的 DashScope 后执行通过，没有绕过审批。
3. 旧规则脚本自称离线，但读取本机配置，首次补跑尝试连接 SMTP 并在 DNS 阶段失败，没有真实发信。该次运行可能留下 eval 专用测试记录，不作为通过证据；没有自动删除可能已有的评测数据。现已从脚本内部强制隔离，并以子进程测试验证危险环境配置无法改变指定的开发库。
4. Docker 构建提示依赖漏洞后，定位并更新 source-map-js 兼容补丁，再运行前端脚本、构建、浏览器和镜像验证。

## 证据边界

- 本轮没有真实 SMTP 投递。mock accepted 不证明老师收到了邮件；CAS 不等于外部副作用端到端 exactly-once。
- 真实模型5项为一次固定样例验收，不是总体成功率、抽取准确率或成本优势证据。
- 浏览器验收与真实模型验收分别执行；不将它们组合声称成一次完整的浏览器到真实模型验收。
- Zotero 的现有测试经过真实本机 HTTP MCP 协议，官方 Zotero API 响应被模拟；真实账号与 Docker+Zotero 联合验收未完成。
- 单实例的并发上限是资源保护，不是企业级容量测试。进程内线程不提供持久任务恢复。
- 没有修改或重新部署用户正在运行的容器；测试镜像使用独立标签。部署前遵循[部署与验收](../../部署与验收.md)，注意旧数据卷属主及密钥持久保存。
