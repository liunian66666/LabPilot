# 对话文件上传

在对话输入区拖入文件，或点击「添加文件」，即可上传并同步资料库。支持 PDF、TXT、Markdown，可一次选择多个文件；单个文件最多 20MB。TXT / Markdown 使用 UTF-8，PDF 需要可提取的文字，扫描件暂不提供 OCR。

成功入库后，对话展示文件卡片；刷新、切换会话后返回均可恢复。上传期间阻止发送消息和切换会话，避免文件归属错乱。失败显示明确提示，不生成成功卡片。

上传直接调用现有 `/api/v1/docs/upload` 入库流程，增加可选 `session_id` 保存对话回执。文本提取、切分、向量索引共用资料库服务，不消耗一次 Agent 模型调用来决定是否上传。原始文件不长期保存，保留解析后的文本和索引。

后续对话将当前会话最近十个文件的名称和 document_id 作为元数据提供给 Agent。`search_knowledge` 支持指定 document_id，按文档及用户过滤检索；多份文件指代不清时由 Agent 澄清。会话关联表示当前讨论资料，入库后的文档也可通过用户资料库检索。

## 真实模型复验（2026-09-29）

全部后端回归 45 passed，前端生产构建通过，浏览器上传验收 6/6。

`evals/chat_upload_live.py` 使用当前配置的真实模型和向量服务，隔离业务库与检查点库、邮件 mock。上传两份事实冲突的实验文档，随后通过 `/chat/stream` 提问目标会话的资料：模型调用 `search_knowledge` 并传入目标 document_id，返回准确率 94.6%、代号 LP-946-X7、日期 2030-06-18，没有混入另一份文档的 12.3% / OLD-123；回复已存入会话历史。实际向量召回执行，流式输出 25 段，本次耗时约 9.61 秒。详细结果见 `test-results/chat-upload/live-model.json`。

真实复验发现并修复共享异步向量客户端跨事件循环的问题：上传运行在 ASGI 循环，Agent 工具在短期循环中执行；向量请求现通过后台线程调用同步客户端，避免跨循环复用异步连接。新增回归覆盖两个独立循环及非阻塞执行。

当前重排服务返回 HTTP 401，已按既有机制降级；本次真实问答通过不代表重排鉴权正常。需另行核对服务端重排服务地址、模型及密钥配置。

后端重新启动后启用新上传处理与 Agent 工具参数；前端开发服务器自动更新，刷新页面即可。
